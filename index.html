Aim

To design and implement a CPU Scheduling Simulator that visually demonstrates different CPU scheduling algorithms — First-Come, First-Served (FCFS), Shortest Job First (SJF) (preemptive/non-preemptive), Priority (preemptive/non-preemptive), Round Robin, and Multilevel Queue — and analyzes their performance using Average Waiting Time, Average Turnaround Time, and Throughput, while featuring a live animation of Gantt chart generation as processes transition among the Ready Queue, CPU, Waiting Queue, and Terminated states.

Theory & Applications

1. Introduction to CPU Scheduling

A computer system may have several processes waiting to be executed, but the CPU can execute only one process at a time on a single CPU core. Therefore, the operating system needs to decide which process should be given the CPU next.

This decision-making process is called CPU Scheduling. The component of the operating system responsible for selecting the next process is called the CPU Scheduler.

Simple Example:

Suppose P1, P2 and P3 are waiting for the CPU. The scheduler selects one process according to the selected scheduling algorithm. Different algorithms may select the processes in different orders, resulting in different waiting times and turnaround times.

2. Important Terms

Process

A process is a program that is currently being executed. In this simulator, processes are represented as P1, P2, P3, and so on.

Arrival Time (AT)

Arrival Time is the time at which a process becomes available for execution and enters the ready queue.

Example: If P1 has Arrival Time = 2, P1 becomes available to the scheduler at time 2.

Burst Time (BT)

Burst Time is the total amount of CPU time required by a process to complete its execution.

Example: If P1 has Burst Time = 5, it requires 5 units of CPU time.

Completion Time (CT)

Completion Time is the time at which a process finishes its execution.

Turnaround Time (TAT)

Turnaround Time represents the total time taken by a process from its arrival until its completion.

TAT = CT − AT

Waiting Time (WT)

Waiting Time is the amount of time a process spends waiting in the ready queue for CPU execution.

WT = TAT − BT

Throughput

Throughput represents the number of processes completed per unit of time. A higher throughput generally means that more processes are completed in a given period.

Throughput = Number of Completed Processes / Total Execution Interval

3. Preemptive and Non-Preemptive Scheduling

Non-Preemptive Scheduling

In non-preemptive scheduling, once a process gets the CPU, it continues execution until its CPU burst is completed. The scheduler does not forcibly remove the process from the CPU.

Example:
P1 executes from 0 to 5. Even if another process arrives during this period, P1 continues until it completes.

Non-preemptive scheduling is used by:

  • First Come, First Serve (FCFS)
  • Shortest Job First (SJF) Non-Preemptive
  • Priority Non-Preemptive
  • Queue 1 of Multilevel Queue

Preemptive Scheduling

A running process can be interrupted before completing its CPU burst. The CPU is then assigned to another process.

Preemption is useful when the operating system needs to provide quick response or give preference to another process.

Preemptive scheduling is used by:

  • Shortest Job First (SJF) Preemptive
  • Priority Preemptive
  • Round Robin
  • Queue 0 of Multilevel Queue

4. First Come First Serve (FCFS)

First Come First Serve (FCFS) is one of the simplest CPU scheduling algorithms. The process that arrives first is selected first.

First Process to Arrive → First Process to Execute

Characteristics

  • It is a non-preemptive scheduling algorithm.
  • Processes are normally executed according to arrival order.
  • It is simple to understand and implement.
  • It does not require a time quantum.
  • It can suffer from the Convoy Effect.

Example

Process Arrival Time Burst Time
P1 0 5
P2 1 3
P3 2 2
P1 P2 P3
0 5 810

Since P1 arrives first, it executes first. After P1 completes, P2 executes, followed by P3.

5. Shortest Job First (SJF)

Shortest Job First (SJF) selects the available process having the smallest burst time.

Your simulator supports both:

  • SJF Non-Preemptive
  • SJF Preemptive

SJF Non-Preemptive

The process with the shortest burst time is selected from the currently available processes. Once selected, it continues until its burst is completed.

SJF Preemptive

The preemptive version is commonly known as Shortest Remaining Time First (SRTF). The scheduler continuously checks the remaining CPU time of available processes and selects the process with the smallest remaining time.

Important:

In the preemptive version, a newly arrived process can interrupt the currently running process if its remaining burst time is smaller.

Advantage

SJF can provide a low average waiting time when the burst times of processes are known accurately.

Disadvantage

Long processes may have to wait for a long time if shorter processes continuously arrive. This situation is called starvation.

6. Round Robin (RR)

Round Robin is a preemptive scheduling algorithm commonly used in time-sharing systems.

Each process receives a fixed amount of CPU time called the Time Quantum.

Time Quantum = Maximum CPU time given to a process in one turn

Example

Suppose the time quantum is 2 units and P1 requires 5 units of CPU time.

P1 → 2 units
P1 → 2 units
P1 → 1 unit

If the process does not finish during its time quantum, it is placed back into the ready queue and another process gets the CPU.

Effect of Time Quantum

  • Small quantum: More frequent context switching and better responsiveness.
  • Large quantum: Fewer context switches and behavior becomes closer to FCFS.
Simulator Tip:

Try the same set of processes with quantum values 1, 2, 4 and 6. Compare the Gantt charts and average waiting times.

7. Priority Scheduling

In Priority Scheduling, every process is assigned a priority. The scheduler selects the process according to its priority value.

Rule used in this simulator:
Smaller priority number = Higher priority

Example

Process Priority
P1 3
P2 1
P3 2

The execution preference will be:

P2 → P3 → P1

because:

3 < 2 < 1

Types supported by this simulator

  • Non-Preemptive Priority: the selected process completes before another process is selected.
  • Preemptive Priority: a newly available higher-priority process can interrupt the running process.

8. Multilevel Queue Scheduling

Multilevel Queue Scheduling divides processes into different queues. Each queue can use a different scheduling algorithm.

Your simulator implements two queues:

Queue Scheduling Algorithm
Queue 0 Round Robin
Queue 1 FCFS

While adding a process, the user can select:

Queue 0 → Round Robin
Queue 1 → FCFS

In this implementation, Queue 0 is given preference whenever a Queue 0 process is ready. Queue 1 processes are considered when Queue 0 has no ready process.

Example:

If P1 belongs to Queue 0 and P2 belongs to Queue 1, and both are ready, the simulator gives CPU preference to P1 because Queue 0 has higher preference.

9. Process States in the Simulator

The simulator visually represents the movement of processes between different CPU scheduling states.

Ready Queue

Contains processes that are ready to execute but are waiting for the CPU.

CPU / Running State

Contains the process that is currently being executed by the CPU.

Waiting Queue

A process may temporarily leave the CPU when it is preempted or when its current time slice ends. The simulator visually represents this transition through the Waiting Queue.

Terminated

A process enters the Terminated state after completing its required CPU execution.

Ready Queue → CPU → Terminated
CPU → Waiting → Ready Queue

10. Gantt Chart

A Gantt Chart is a graphical representation of process execution over time. It shows which process is using the CPU at a particular time.

P1 P2 P3
0 5 810

From this chart:

  • P1 executes from time 0 to 5.
  • P2 executes from time 5 to 8.
  • P3 executes from time 8 to 10.

Your simulator provides both a Live Gantt Chart, which is built while the simulation is running, and a Final Gantt Chart, which is displayed after the simulation completes.

11. Performance Metrics

The simulator calculates the following performance measures after the scheduling process is completed.

Average Waiting Time

It is the average amount of time that all processes spend waiting for CPU execution.

Average Waiting Time = Σ Waiting Time / Number of Processes

Average Turnaround Time

It represents the average total time taken by all processes from arrival to completion.

Average Turnaround Time = Σ Turnaround Time / Number of Processes

Throughput

Throughput represents how many processes are completed during a given execution interval.

Throughput = Number of Processes / (Last Completion Time − First Arrival Time)

12. Comparison of Scheduling Algorithms

Algorithm Type Main Selection Rule Special Parameter
FCFS Non-Preemptive First arrival None
SJF Preemptive / Non-Preemptive Shortest burst / remaining time None
Round Robin Preemptive Fixed time slice Time Quantum
Priority Preemptive / Non-Preemptive Highest priority Priority
Multilevel Queue Preemptive between queues Queue preference Time Quantum

13. Applications of CPU Scheduling

CPU scheduling is an important part of modern operating systems and computing systems.

  • Operating Systems: Determines which process receives CPU time.
  • Multitasking: Allows multiple applications to share CPU resources.
  • Time-Sharing Systems: Round Robin can provide responsive CPU access to multiple users and applications.
  • Servers: Scheduling affects response time and the number of requests handled by the system.
  • Real-Time Systems: Priority scheduling can give important tasks preference.
  • Cloud Computing: Scheduling techniques are used to allocate computing resources among multiple workloads.
Procedure

The following steps show how to simulate and analyze CPU scheduling algorithms using the web-based simulator.

Steps for CPU Scheduling Simulation
  1. Select an algorithm from the "Scheduling Algorithm" dropdown (FCFS, SJF, Round Robin, Priority, or Multilevel Queue).
  2. Choose a mode (only appears for SJF and Priority): select "Non‑Preemptive" or "Preemptive" using the radio buttons.
  3. Enter the Time Quantum (only appears for Round Robin and Multilevel Queue) — this is how long each turn on the CPU lasts before a process is moved to the back of the queue.
  4. Click "Add Process" to open the process form and enter:
    • Arrival Time – when the process becomes ready.
    • Burst Time – total CPU time it needs.
    • Priority – only shown for Priority scheduling (lower number = higher priority).
    • Queue Type – only shown for Multilevel Queue (0 = goes into the Round Robin queue, 1 = goes into the FCFS queue).
    • Process Color – used to identify the process in the Gantt chart and animation.
  5. Repeat step 4 for every process you want to test (at least 2–3 processes are recommended so scheduling differences are visible).
  6. Click Submit to run the algorithm. The live animation begins automatically, showing processes moving through Ready → CPU → (Waiting →) Terminated, with a Gantt chart building up in real time.
  7. Use the Play/Pause, Restart, Stop, and Speed slider controls to control the animation.
  8. Once the animation completes, the final Gantt chart, the result table (Arrival, Burst, Completion, Waiting, Turnaround for every process), and the performance metrics appear below.
  9. Click Clear All to remove all processes and start a fresh comparison, e.g. to run the same processes under a different algorithm.
  10. Click Back to Home to return to the index page of the V‑Lab.

                        if (!ready.length) {
                            const nextArrival = Math.min(...remaining.map(p => p.arrival));

                        if (time < p.arrival) {
                            ganttLog.push({ id: 'Idle', color: '#ccc', duration: p.arrival - time });
                            time = p.arrival;

                        if (!ready.length) {

                            if (!future.length) break;

                            recordBlock(null, next - time);
                            time = next;
                            running = null;
                            continue;

                            const priorityDifference = a.priority - b.priority;
                            if (priorityDifference !== 0) return priorityDifference;

                            if (isPreemptive && a === running) return -1;
                            if (isPreemptive && b === running) return 1;
                            return order(a, b);
                        });
                        const current = ready[0];
                        let duration = current.remaining;
                        if (isPreemptive) {
                            const future = pList.filter(p => p.remaining > EPS && p.arrival > time + EPS);
                            const nextArrival = future.length ? Math.min(...future.map(p => p.arrival)) : Infinity;
                            duration = Math.min(duration, nextArrival - time);
                        }
                        if (duration <= EPS) throw new Error('Priority scheduler made no progress');
                        recordBlock(current, duration);
                        time = +(time + duration).toFixed(10);
                        current.remaining = +Math.max(0, current.remaining - duration).toFixed(10);
                        running = current;
                        if (current.remaining <= EPS) {
                            current.remaining = 0;
                            logCompletion(current);
                            completed++;
                            running = null;
                        }
                        }
                    } else if (algo === 'Round Robin') {
                        const EPS = 1e-9;
                        if (!Number.isFinite(quantum) || quantum <= 0) {
                        alert('Enter a positive time quantum for Round Robin.'); return;
                        }
                        const arrivals = [...pList].sort((a, b) => a.arrival - b.arrival || a.id - b.id);
                        const ready = [];
                        let nextIndex = 0;
                        function enqueueArrivals() {
                        while (nextIndex < arrivals.length && arrivals[nextIndex].arrival <= time + EPS) {
                            ready.push(arrivals[nextIndex++]);
                        }
                        }
                        while (completed < n) {
                        enqueueArrivals();
                        if (!ready.length) {
                            const nextTime = arrivals[nextIndex].arrival;
                            recordBlock(null, nextTime - time);
                            time = nextTime;
                            enqueueArrivals();
                        }
                        const current = ready.shift();
                        const duration = Math.min(quantum, current.remaining);
                        recordBlock(current, duration, undefined, false); // Preserve RR quantum boundaries
                        time = +(time + duration).toFixed(10);
                        current.remaining = +Math.max(0, current.remaining - duration).toFixed(10);
                        enqueueArrivals(); // Arrivals precede requeued process
                        if (current.remaining > EPS) ready.push(current);
                        else {
                            current.remaining = 0;
                            logCompletion(current);
                            completed++;
                        }
                        }
                    } else if (algo === 'Multilevel') {
                        // Absolute priority: Q0 = Round Robin; Q1 = FCFS, preempted by Q0.
                        const EPS = 1e-9;
                        if (!Number.isFinite(quantum) || quantum <= 0) {
                        alert('Enter a positive time quantum for Queue 0.'); return;
                        }
                        if (pList.some(p => ![0, 1].includes(Number(p.queueType)))) {
                        alert('Every process must belong to Queue 0 or Queue 1.'); return;
                        }
                        const high = pList.filter(p => Number(p.queueType) === 0)
                        .sort((a, b) => a.arrival - b.arrival || a.id - b.id);
                        const low = pList.filter(p => Number(p.queueType) === 1)
                        .sort((a, b) => a.arrival - b.arrival || a.id - b.id);
                        const rrReady = [];
                        let hi = 0, lo = 0;
                        function enqueueHigh() {
                        while (hi < high.length && high[hi].arrival <= time + EPS) {
                            rrReady.push(high[hi++]);
                        }
                        }
                        while (completed < n) {
                        enqueueHigh();
                        if (rrReady.length) {
                            const current = rrReady.shift();
                            const duration = Math.min(current.remaining, quantum);
                            recordBlock(current, duration, 0, false);
                            time = +(time + duration).toFixed(10);
                            current.remaining = +Math.max(0, current.remaining - duration).toFixed(10);
                            enqueueHigh();
                            if (current.remaining > EPS) rrReady.push(current);
                            else {
                            current.remaining = 0;
                            logCompletion(current);
                            completed++;
                            }
                        } else if (lo < low.length && low[lo].arrival <= time + EPS) {
                            const current = low[lo];
                            const nextHighArrival = hi < high.length ? high[hi].arrival : Infinity;
                            const duration = Math.min(current.remaining, nextHighArrival - time);
                            if (duration <= EPS) {
                            enqueueHigh();
                            if (!rrReady.length) throw new Error('Multilevel scheduler made no progress');
                            continue;
                            }
                            recordBlock(current, duration, 1, true);
                            time = +(time + duration).toFixed(10);
                            current.remaining = +Math.max(0, current.remaining - duration).toFixed(10);
                            if (current.remaining <= EPS) {
                            current.remaining = 0;
                            logCompletion(current);
                            completed++;
                            lo++;
                            }
                        } else {
                            const nextHigh = hi < high.length ? high[hi].arrival : Infinity;
                            const nextLow = lo < low.length ? low[lo].arrival : Infinity;
                            const nextTime = Math.min(nextHigh, nextLow);
                            if (!Number.isFinite(nextTime)) throw new Error('Unfinished multilevel processes');
                            recordBlock(null, nextTime - time);
                            time = nextTime;
                        }
                        }
                    } else {
                        throw new Error(`Unsupported scheduling algorithm: ${algo}`);

Result

After a simulation finishes, you will see:

  1. Final Gantt Chart — a horizontal bar chart where each colored block represents a process running on the CPU for a certain duration; the numbers under the chart mark the time at which each block starts.
  2. Result Table — one row per process, showing:
    • PID — process identifier
    • Arrival and Burst — the values you entered
    • Completion — the time it finished
    • Waiting and Turnaround — calculated as explained in Section 2.3
  3. Metrics box:
    • Average Waiting Time — lower is generally better; it tells you how long processes typically sat idle in the ready queue.
    • Average Turnaround Time — lower is generally better; it tells you the typical total time from a process's arrival to its completion.
    • Throughput — higher is generally better; it tells you how many processes the system completes per unit of time.

Use the same set of processes across different algorithms (just change the dropdown and click Submit again) to directly compare these three numbers and see, empirically, why algorithms like SRTF tend to minimize average waiting time while FCFS is simplest but can perform worst under the convoy effect.
